# Provider memory targets

The compiled shared SDK binds explicit provider operations to the reviewed database, action, fact and SQLite lifetime revision. Unknown provider targets stay unresolved; revision counters never grant access.

SDK24/preview.51 adds the same bounded target shape and shared approval presentation to Web and Desktop. The actual Hermes provider holds an atomic SQLite scope from revision validation through commit, without changing frozen tool schemas. See [[owned-tool-calls#Owned tool calls]] for attached conversation custody.

Local bundled Holographic verification covers all nine fact_store actions and both feedback choices across three middleware boundaries and A/B/A. Failed vector generation rolls back the fact/entity changes; a competing process cannot write between the check and commit. This is SQLite connection-lifetime custody, not a durable revision carried across new connections, power-loss recovery, built-in/provider atomic mirrors, all providers or installed/native/account verification.

## Provider database admission

The compiled consumer compares every reviewed provider target field before dispatch. A changed database, operation, fact or revision refuses without sending tools.call, even when the outer digest is unchanged.
